# reaper-scripts

REAPER Lua scripts for audio restoration and first-pass, top-down
mixing/mastering. Distributed as a [ReaPack](https://reapack.com/) repository.

## Layout

```
Scripts/
  Restoration/       # de-noise, de-hum, de-click, de-ess, etc.
  Mixing-Mastering/  # top-down gain staging, bus processing, etc.
lib/
  rns_core/           # portable, unit-tested Lua modules — no REAPER API calls
  rns_reaper/          # thin REAPER-API glue (audio accessors, etc.) — not unit tested
spec/                 # busted unit tests for lib/rns_core
index.xml             # ReaPack repository index (generated by reapack-index)
```

Scripts are kept thin: shared logic (gain/level math, RMS/LUFS analysis,
track/FX helpers) lives in `lib/rns_core` and is pulled in with `require()`,
rather than duplicated across scripts. Code that must call into `reaper.*`
in ways too involved to usefully mock (e.g. walking an audio accessor)
lives in `lib/rns_reaper` instead, kept as thin as possible.

## Installing in REAPER

Once this repo has scripts and a populated `index.xml`, add it in REAPER via
**Extensions > ReaPack > Import a repository...** using this repo's raw
`index.xml` URL.

For local development without ReaPack, symlink or copy files from `Scripts/`
into your REAPER `Scripts` resource directory.

## Development

Requires [Lua](https://www.lua.org/) 5.1 (REAPER's embedded Lua version) plus:

- [luarocks](https://luarocks.org/) to install the tools below
- [luacheck](https://github.com/mpeterv/luacheck) — lint (`luacheck .`)
- [StyLua](https://github.com/JohnnyMorganz/StyLua) — format (`stylua .`)
- [busted](https://lunarmodules.github.io/busted/) — unit tests (`busted`)

```bash
luarocks install luacheck
luarocks install busted
# StyLua ships as a standalone binary; see its releases page, or:
#   cargo install stylua / npm install -g @johnnymorganz/stylua-bin

luacheck .
stylua --check .
busted
```

`lib/rns_core` code should stay REAPER-API-agnostic where possible so it can
be unit tested directly; where it must call into `reaper.*`, extend
`spec/support/reaper_mock.lua` with the stubs needed rather than skipping
tests.

## Adding a new script

1. Drop a `.lua` file into `Scripts/Restoration/` or `Scripts/Mixing-Mastering/`.
2. Give it a standard REAPER/ReaPack header (`@description`, `@author`,
   `@version`, `@about`).
3. Pull shared logic from `lib/rns_core` instead of reimplementing it.
4. Regenerate `index.xml` with `reapack-index` before tagging a release.
